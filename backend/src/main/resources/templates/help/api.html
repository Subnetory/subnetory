Authentification

Obtenir un jeton JWT avec vos identifiants :

Obtenir un jeton curl -s -X POST /api/v1/auth/token -H "Content-Type: application/json" -d '{"username":"...","password":"..."}'

Si le MFA est actif sur le compte, ajouter le champ totpCode (ou un code de récupération) dans le corps de la requête :

Avec MFA curl -s -X POST /api/v1/auth/token -H "Content-Type: application/json" -d '{"username":"...","password":"...","totpCode":"123456"}'

Utiliser le jeton obtenu :

Appeler l'API curl -s /api/v1/addresses -H "Authorization: Bearer <token>"

Révoquer un jeton

Les jetons JWT de l'API sont révocables avant leur expiration naturelle, individuellement ou globalement pour votre compte :

Déconnexion (ce jeton uniquement) curl -s -X POST /api/v1/auth/logout -H "Authorization: Bearer <token>"
Invalider tous mes jetons existants curl -s -X POST /api/v1/auth/logout-all -H "Authorization: Bearer <token>"

Comptes d'automatisation

Tout compte local est créé avec un mot de passe temporaire qui doit être remplacé avant tout usage normal — l'émission d'un jeton est refusée (403 PASSWORD_CHANGE_REQUIRED) tant que ce changement n'a pas eu lieu.

Remplacer le mot de passe temporaire (aucun jeton requis) curl -s -X POST /api/v1/auth/change-password-required -H "Content-Type: application/json" -d '{"username":"...","currentPassword":"...","newPassword":"..."}'

Pour un compte de service en lecture seule limité à un périmètre, attribuer le rôle ROLE_READ_ONLY et restreindre ses contextes autorisés.
