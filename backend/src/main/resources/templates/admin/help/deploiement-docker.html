Déploiement Docker Compose & HTTPS

Installation autonome avec PostgreSQL inclus, secrets fichiers, et exposition HTTPS optionnelle.

Générer les secrets

Trois secrets sont requis avant le premier démarrage : le secret JWT, le mot de passe administrateur temporaire et le mot de passe PostgreSQL. Un script dédié les génère aléatoirement sans jamais afficher leur valeur, et applique des permissions restrictives (icacls sous Windows, chmod 600 sous Linux/macOS).

PowerShell pwsh -File .\scripts\init-compose.ps1
Bash ./scripts/init-compose.sh

Un quatrième secret optionnel, subnetory_backup_encryption_key, active le chiffrement des sauvegardes (désactivé par défaut) :

Avec chiffrement des sauvegardes pwsh -File .\scripts\init-compose.ps1 -WithBackupEncryption
Le script refuse d'écraser un secret existant. L'option -Force/--force est réservée à une rotation volontaire et coordonnée — jamais une commande de réparation générique.

Démarrer la stack

Depuis backend/ docker compose up -d --build

Les migrations Flyway s'appliquent automatiquement au démarrage. PostgreSQL reste strictement interne au réseau Compose, jamais publié sur un port de l'hôte.

Protection des secrets sur le poste

Les permissions restrictives du script bloquent l'accès à un autre compte non privilégié sur la même machine — elles ne protègent pas contre un attaquant qui obtiendrait les droits de votre propre compte ou les droits administrateur, ni contre le vol d'un disque éteint sans chiffrement de volume (BitLocker/LUKS).

Point d'attention particulier si le dossier du dépôt est synchronisé par un client cloud (OneDrive Known Folder Move notamment) : le dossier secrets/, bien que git-ignoré, partirait alors en clair vers le cloud. Vérifiez qu'aucune synchronisation cloud ne couvre ce dossier.

HTTPS clé en main (overlay Caddy, optionnel)

docker-compose.https.yml ajoute un reverse proxy Caddy devant l'application, sans infrastructure externe à gérer (pas de certificat à générer ou installer manuellement).

ModeUsageCertificat
InterneRéseau d'entreprise, pas de domaine publicAuto-signé (avertissement navigateur normal)
PublicDomaine résolu vers cet hôte, ports 80/443 accessibles depuis InternetLet's Encrypt automatique, renouvelé sans intervention
Mode interne — copier le Caddyfile Copy-Item deploy\Caddyfile.internal deploy\Caddyfile
Démarrer avec l'overlay docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build

L'overlay active automatiquement la confiance envers le proxy interne (SUBNETORY_SECURITY_TRUSTED_PROXY) pour que le rate limiting par IP et l'audit d'authentification restent exacts — sans cela, toutes les requêtes seraient comptées comme venant d'une seule IP (le conteneur Caddy).

Le volume caddy_data conserve les certificats entre redémarrages — ne pas le supprimer sans raison en mode public (nouvelles demandes Let's Encrypt, risque de limitation de débit en cas de suppressions répétées).
